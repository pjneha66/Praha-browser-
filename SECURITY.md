# Reporting a Praha security issue

No production builds are supported yet. Do not use an unsigned preview as a daily browser or assume it receives security updates automatically.

For a suspected vulnerability in Praha, use **Security → Report a vulnerability** in the project's repository if private reporting is enabled. If the option is unavailable, open an issue requesting a private contact channel **without disclosing the vulnerability**. The maintainers must establish and verify a private reporting channel before a public release. Do not attach passwords, tokens, browsing history, or unredacted profiles.

In the private report, include the affected revision or release, operating system, whether a fresh profile is affected, and the impact you observed. If the issue affects the unmodified upstream engine too, coordinate privately with [upstream security](https://www.mozilla.org/security/). Praha does not operate or promise a bug bounty.
