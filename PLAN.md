# Praha Browser implementation plan

**Goal:** an independently branded desktop and Android browser with user-selectable tracking protection, working WebExtensions, ad blocking on first launch and a maintained security release channel. Preserve legal notices and compatibility identifiers; distinguish user-visible branding from source provenance.

| Phase | Implemented in source | Remaining acceptance criteria |
| --- | --- | --- |
| 0–1 · Identity and desktop | Desktop branding directory, `mozconfig-praha`, app basename/vendor, UA changes, primary icon/wordmark and Windows tile assets. | Inspect packaged binaries, launcher, alternate icons, OS metadata, installer text and localized UI on each platform. |
| 2 · Android identity | Fenix package rebrand, new default launcher artwork and About mark, Android mozconfig. No Firefox string found in `mobile/locales/` (build metadata, not the Fenix translations). | Audit translated Fenix resources, optional icons and remaining service integrations on device. iOS in this tree is a prototype, not a release target. |
| 3 · UI | Default desktop tab and toolbar palette, menu icon, urlbar and popup styling, branded About dialog, local `about:branding` first-run page, privacy-first Settings, Add-ons card and permission-prompt styling. Android Compose accent colors, Settings order and About screen use the new identity. | Complete toolbar/urlbar, menu, popup, doorhanger, other about-page and Android tab switcher/menu/onboarding layouts. Review accessibility, themes, localization and interactions on running builds. |
| 4 · Privacy | Desktop prefs included after upstream defaults. Fresh profiles opt into the engine's Strict category. DoH uses TRR prefs, HTTPS-only and shutdown sanitization enabled. Android telemetry defaults off and Strict defaults on. Desktop distribution stages a hash-pinned signed uBlock XPI. | Test actual effective prefs, blocking, opt-out persistence, extension signatures and network requests. Package and verify uBlock on Android; finish mobile telemetry/account/Sync/Pocket/VPN audit. Verify search engine and new-tab behavior, not just pref strings. |
| 5 · Build | Desktop and Android configs reach toolchain discovery. Fixed configure syntax, preference input and branded package paths. | Full compilation, packaging, install and launch on provisioned hosts. Verify `about:branding` in the packaged binary. Production signing needs real publisher credentials. |
| 6 · Legal and docs | Praha README, contributor guidance, security reporting and source-distribution checklist. | Audit remaining artwork/strings, verify private reporting, third-party notices and publish exact corresponding source alongside releases. |
| 7 · CI and release | PR input checks; manual full build jobs for prepared desktop/Android runners; desktop smoke test and Android default-setting assertions. | Provision runners, pass build/runtime checks, sign, verify and distribute installers/APKs. No signed artifacts or project update server are verified. |
| 8 · Maintenance | ESR integration and extension update checklist. | Select and record a supported ESR base, assign owners, integrate and test security updates continuously. |

## Current verification

`python3 tools/praha/test_inputs.py` exercises hash-mismatch rejection, Windows tile references and Android privacy preference XML. `./mach python tools/praha/test_preprocessing.py` also passes for branded and unbranded inputs. Both desktop and Android `./mach build` attempts in the development sandbox stopped during toolchain download, before compilation. The signed XPI's release metadata was available but its download host was blocked. No binary, APK, first-run behavior or signature has been certified by these source checks.

Two release gates remain unverified by a full build. (1) Android signing continuity: `release_praha_android.py` and `make_webapp_apk.py` now generate a persistent keystore under `~/.praha/` on first use (overridable via the `keystore_path` argument) and reuse it afterwards, so consecutive releases of a package share one signer certificate; only the two-build reuse path has been exercised against the local Android SDK, not a shipped update over an installed release. (2) CRX-to-XPI sideload: `mozconfig-praha` and `tools/praha/android.mozconfig` export an empty `MOZ_REQUIRE_SIGNING` (which makes the `xpinstall.signatures.required` preference authoritative — note `0` aborts configure, the value must be empty) and `browser/app/profile/praha.js` defaults that preference to `false`, so converted unsigned XPIs should install; setting the preference back to `true` in about:config re-enforces Mozilla-style signing. Installing an actual converted XPI in a running build has not been tested. (3) DoH provider switching: because WebExtensions cannot write preferences, `toolkit/components/extensions/parent/ext-storage.js` mirrors the allowlisted `media-downloader@prahabrowser.org` extension's `praha_doh_provider` storage key into `network.trr.uri`/`mode`/`bootstrapAddress` on every `storage.local` set path; the mirror is syntax-checked only and has not been exercised in a running build.

See [build instructions](README.md) and the [release gates](docs/praha/release.md) for the commands and manual checks.
